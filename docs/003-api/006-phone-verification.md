# 006. 휴대폰 인증 앱 연동 가이드

## 엔드포인트와 시간 계약

| API | 용도 |
|---|---|
| `POST /api/v1/verifications` | 인증번호 SMS 발송 |
| `POST /api/v1/verifications/admin` | 기존 관리자 테스트용 발송, SMS 없이 고정 코드 사용 |
| `PATCH /api/v1/verifications` | 인증번호 검증 및 인증 토큰 발급 |

발송 요청은 기존과 같이 `phoneNumber`를 받습니다. 일반·관리자 발송 모두 성공 시 다음 필드를 반환합니다.

```json
{
  "status": 200,
  "data": {
    "expiresAt": "2026-11-02T15:03:00",
    "resendAvailableAt": "2026-11-02T15:01:00+09:00"
  }
}
```

- `expiresAt`: 발급 시 결정한 인증번호 만료 시각. 기존 앱 호환성을 위해 시간대 없는 KST 형식을 유지합니다. 오입력해도 연장되지 않습니다.
- `resendAvailableAt`: 발송 성공 후 설정한 60초 재발송 제한의 실제 종료 시각. KST 오프셋 `+09:00`을 포함합니다.
- 두 필드의 초 이하 소수점은 포함될 수 있습니다. ISO 8601 파서를 사용하고 고정 문자열 길이에 의존하지 않습니다.
- SMS 처리 시간 때문에 두 시각의 차이가 항상 정확히 2분인 것은 아닙니다.

## 제한 오류

재발송 제한과 발송 한도 초과는 기존 HTTP 429와 오류 JSON 본문을 그대로 유지합니다. 대기 시간은 `Retry-After` 응답 헤더에 음수가 아닌 정수 초로 제공합니다.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 45
Content-Type: application/json
```

```json
{
  "status": 429,
  "data": {
    "errorCode": "TOO_MANY_REQUESTS",
    "message": "재발송 제한 시간이 지나지 않았습니다."
  }
}
```

| `errorCode` | 의미 | `Retry-After` |
|---|---|---|
| `TOO_MANY_REQUESTS` | 재발송 대기 중 | 해당 전화번호 재발송 제한이 풀릴 때까지 남은 초 |
| `DAILY_SMS_LIMIT_EXCEEDED` | 24시간 발송 한도 50회 초과 | 해당 전화번호 발송 카운터가 만료될 때까지 남은 초 |

Redis에 저장된 실제 제한 만료 시각과 오류 처리 시각의 차이를 초 단위로 올림합니다. 오류 발생 시점부터 60초 또는 24시간을 새로 시작하지 않습니다. 남은 시간이 0 이하이면 `0`을 반환합니다.

기존 `ErrorData`의 `errorCode`, `field`, `message`와 null 필드 생략 규칙은 변경하지 않습니다. 성공 응답과 관련 없는 오류에는 `Retry-After` 헤더를 추가하지 않습니다. 만료 시간이 없는 비정상 제한 데이터는 내부 오류로 처리하고 임의의 대기 시간을 반환하지 않습니다.

## 앱 표시 기준

- 표시 문구는 앱 문자열 리소스로 관리하고 `data.errorCode`로 분기합니다. 서버 `message` 문자열을 비교하지 않습니다.
- 발송 성공 후 `resendAvailableAt`까지의 차이로 재발송 타이머를 표시합니다. 남은 시간은 `max(0, ceil(종료 시각 - 현재 시각))`로 계산합니다.
- 제한 오류 후 `Retry-After` 헤더의 정수 초로 타이머를 보정합니다. 예를 들어 `45`이면 응답 수신 시점부터 45초 대기합니다. 안드로이드에서는 오류 응답의 헤더를 읽고 기존 오류 DTO 매핑은 그대로 사용합니다.
- 헤더가 없는 이전 서버 응답이나 값이 잘못된 경우에는 일반 제한 안내를 표시하고, 임의로 60초 또는 24시간을 다시 시작하지 않습니다.
- 인증 입력 타이머는 `expiresAt`을 KST로 해석해 계산합니다. 오입력 응답을 받아도 3분으로 다시 시작하지 않습니다.
- 화면 갱신 때마다 종료 시각과의 차이를 계산하여 앱이 백그라운드에 있던 시간을 반영합니다. 서버 호출을 매초 실행하지 않습니다.
- 재발송 대기는 “인증번호는 {초}초 후 다시 받을 수 있어요”처럼, 발송 한도는 “발송 한도를 초과했어요. {재시도 시각} 이후 다시 시도해주세요”처럼 안내할 수 있습니다.
- 발송 한도는 최초 카운터 생성부터 24시간입니다. 자정 초기화 또는 마지막 발송부터 24시간으로 해석하지 않으며 “내일 다시 시도해주세요”로 안내하지 않습니다.
- 앱 재실행 시 저장한 종료 시각으로 복원할 수 있습니다. 다른 기기의 추가 요청은 다음 서버 응답으로 보정하며, 이번 변경에는 인증 상태 조회 API나 실시간 동기화가 포함되지 않습니다.
- 기기 시계 오차나 네트워크 지연이 있을 수 있으므로 타이머가 0이어도 최종 허용 여부는 서버 응답을 따릅니다.

## 기존 앱 호환성과 배포

오류 JSON 템플릿은 그대로 유지하며 기존 앱은 새 헤더를 읽지 않아도 됩니다. 성공 응답에 추가한 `resendAvailableAt`은 이전 서버와 함께 사용할 수 있도록 선택 필드로 받고, `Retry-After` 헤더도 존재할 때만 활용합니다. 서버 배포만으로 기존 앱의 UI 문구나 타이머가 바뀌지는 않습니다.

구현 및 검증은 [휴대폰 인증 만료·재시도 처리](../004-implementation/013-phone-verification.md)를 참고합니다.
