# 001. 홈 여행방 추천 정책

> 이 문서는 홈 화면에서 사용자에게 여행방을 추천할 때 적용하는 제품 정책을 정의합니다.
> 구체적인 DB 모델, 점수 계산식, 상태값, 테스트 방향은 [추천 구현 문서](../004-implementation/002-recommendation.md)를 참고합니다.

---

## 한 줄 요약

홈 추천은 사용자가 아니라 여행방을 하루 최대 3개 추천하는 기능이며, 같은 KST 일자에는 이미 생성된 추천 묶음을 재사용합니다.

---

## 1. 추천 대상

추천을 받을 수 있는 사용자는 아래 조건을 모두 만족해야 합니다.

- 로그인한 사용자입니다.
- 온보딩 설문을 완료했습니다.
- 여행 성향 점수가 존재합니다.

온보딩 또는 설문을 완료하지 않았으면 `availabilityStatus=SURVEY_REQUIRED`로 응답하고 추천 카드를 제공하지 않습니다. 설문 완료 사용자의 프로필이나 여행 성향 데이터가 누락된 경우는 추천 불가 상태로 숨기지 않고 데이터 정합성 오류로 처리합니다.

---

## 2. 추천 후보 기준

추천 후보 여행방은 아래 조건을 모두 만족해야 합니다.

- 삭제되지 않은 여행방입니다.
- 모집 중인 여행방입니다.
- 여행 종료일이 지나지 않았습니다.
- 모집 정원이 마감되지 않았습니다.
- 사용자가 직접 작성한 여행방이 아닙니다.
- 사용자가 여행방의 선호 성별과 선호 나이 조건을 만족합니다.
- 사용자가 이미 참여 신청한 여행방이 아닙니다.
- 사용자가 이미 패스한 여행방이 아닙니다.
- 사용자가 신고한 여행방이 아닙니다.
- 여행방 작성자의 여행 성향 점수가 존재합니다.

참여 신청은 신청 상태와 무관하게 이력이 있으면 추천 후보에서 제외합니다. 거절된 신청도 이미 노출되고 상호작용한 여행방으로 보기 때문에 다시 추천하지 않습니다.

---

## 3. 사용자 설정 필터

관심 여행지와 가능한 여행 기간은 필수 입력이 아닙니다. 사용자가 설정한 경우에만 추천 후보를 좁히는 필터로 사용합니다.

| 사용자 설정 | 추천 후보 필터 |
|---|---|
| 여행지와 날짜 모두 설정 | 여행지와 날짜를 모두 만족하는 여행방 |
| 여행지만 설정 | 여행지를 만족하는 여행방 |
| 날짜만 설정 | 날짜를 만족하는 여행방 |
| 둘 다 미설정 | 여행지와 날짜로 제한하지 않음 |

관심 여행지는 도시 단위 또는 국가 전체 단위로 설정할 수 있습니다. 국가 전체를 선택하면 해당 국가의 모든 도시를 허용합니다.

가능한 여행 기간은 여행방의 동행 방식에 따라 다르게 판단합니다.

| 동행 방식 | 날짜 기준 |
|---|---|
| 전체 동행 | 사용자의 가능한 기간이 여행방 전체 일정을 포함해야 함 |
| 부분 동행 | 여행방 일정과 2일 이상 겹쳐야 함 |
| 식사 동행 | 여행방 일정과 1일 이상 겹쳐야 함 |
| 미정 | 여행방 일정과 1일 이상 겹쳐야 함 |

---

## 4. 추천 점수와 정렬

MVP 추천 점수는 신청자와 여행방 작성자의 여행 성향 유사도를 기준으로 계산합니다. 여행방에 이미 참여한 다른 멤버의 성향은 MVP 점수에 반영하지 않습니다.

추천 정렬은 아래 우선순위를 따릅니다.

1. 여행 성향 적합도가 높은 여행방
2. 여행 시작일이 빠른 여행방
3. 더 최근에 생성된 여행방

추천 카드에는 적합도와 함께 추천 이유, 확인이 필요한 차이점을 보여줄 수 있습니다.

---

## 5. 하루 제공량

- 하루 추천 제공량은 최대 3개입니다.
- 하루 기준은 매일 00:00 KST입니다.
- 같은 사용자에게 같은 날짜의 추천 묶음이 이미 있으면 새로 계산하지 않고 기존 묶음을 재사용합니다.
- 후보가 0~2개만 있어도 그날의 추천 묶음은 확정된 것으로 봅니다.
- 추천 신청이나 패스를 하더라도 같은 날 대체 추천을 추가 생성하지 않습니다.

MVP에서는 하루 추천을 한 번에 확정하므로 추천 가능 횟수는 항상 0으로 응답합니다.

---

## 6. 홈 응답 정책

홈 추천 응답의 `availabilityStatus`는 추천 기능을 사용할 수 있는지를 나타냅니다. 후보가 없거나 저장된 카드가 현재 노출 불가여도 사용 자격이 있다면 `AVAILABLE`입니다.

| 상황 | `availabilityStatus` | 홈 카드 |
|---|---|---|
| 온보딩 또는 설문 미완료 | `SURVEY_REQUIRED` | 없음 |
| 당일 추천 묶음 생성 중 | `GENERATING` | 없음 |
| 추천 가능하지만 후보 없음 | `AVAILABLE` | 없음 |
| 추천 후보 1개 | `AVAILABLE` | 1개 |
| 추천 후보 2개 | `AVAILABLE` | 2개 |
| 추천 후보 3개 이상 | `AVAILABLE` | 상위 3개 |
| 저장된 추천이 모두 현재 노출 불가 상태가 됨 | `AVAILABLE` | 없음 |

추천 후보가 없거나 저장된 추천이 현재 노출 불가 상태가 되더라도 같은 날 추가 추천을 생성하지 않습니다. 모든 정상 응답에서 `remainingFreeCount`는 0이며 카드가 없으면 `recommendations=[]`를 반환합니다.

“최신 추천”은 로그인 회원의 KST 당일 추천 묶음을 의미합니다. 당일 첫 호출에서 생성하고 같은 날 재사용하며, 전날 결과로 대체하지 않습니다. 저장 순위 오름차순으로 노출하고 게시글·호스트 정보는 현재 값, 적합도·추천 이유는 생성 시 저장값을 사용합니다.

설문 완료 후 프로필 누락은 `PROFILE_NOT_FOUND`(404), 여행 성향 누락은 `RECOMMENDATION_TENDENCY_MISSING`(500)로 반환합니다. 생성·조회 중 예상하지 못한 서버 오류는 `INTERNAL_SERVER_ERROR`(500)이며 빈 성공 응답으로 바꾸지 않습니다. 생성 실패로 `FAILED`가 된 묶음은 다음 홈 추천 호출에서 재시도합니다.

추천 API는 다른 홈 섹션과 독립적으로 호출합니다. 추천 실패는 해당 섹션에서 처리하고 홈 초기 구성 및 다른 섹션은 각각 조회합니다. #329에서 생성 중 상태를 `GENERATING`으로 유지하기로 확정했으며, #297 이슈 본문의 생성 중 `AVAILABLE` 설명보다 이 정책을 우선합니다.

---

## 7. 추천 이후 여행방 상태 변화

추천 결과는 생성 시점의 이력으로 유지합니다. 다만 홈 화면에는 현재 신청 가능한 여행방만 노출합니다.

추천 생성 이후 여행방이 아래 상태가 되면 홈 추천 카드에서 숨깁니다.

- 모집이 종료되었습니다.
- 정원이 마감되었습니다.
- 여행 종료일이 지났습니다.
- 삭제되었습니다.
- 현재 사용자가 더 이상 모집 조건을 만족하지 않습니다.
- 현재 사용자의 여행지 또는 가능 날짜 조건을 만족하지 않습니다.
- 현재 사용자가 해당 여행방에 신청, 패스 또는 신고했습니다.

숨겨진 추천을 대체하기 위해 같은 날 새 추천을 추가하지 않습니다. 따라서 추천 생성 시 3개가 저장되었더라도 홈 화면에는 0~3개가 보일 수 있습니다.

홈 추천에는 현재 신청 가능한 여행방만 노출하므로 별도의 신청 가능 여부 필드는 제공하지 않습니다. 실제 신청 요청 시에는 추천 여부와 관계없이 현재 여행방 상태와 모집 조건을 다시 검증합니다.

---

## 8. 패스 정책

사용자가 한 번 패스한 여행방은 이후 추천 후보에서 제외합니다.

MVP에서는 패스 취소 기능을 제공하지 않습니다. 향후 패스 취소가 필요해지면 별도 정책으로 정의합니다.

패스는 `POST /api/v1/mate-recommendations/{recommendationId}/pass`로 처리합니다. 본인의 추천만 패스할 수 있으며 같은 추천을 다시 패스해도 성공으로 처리합니다.
