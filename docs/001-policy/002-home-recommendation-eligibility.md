# 홈 게시글 추천 공통 노출 조건

홈에서 모집글을 추천할 때 적용하는 공통 조건의 기준 문서입니다.
다른 문서에서는 아래 조건을 복사하지 않고 이 문서를 링크하며, 각 추천 고유의 조건만 설명합니다.

## 적용 범위

| 섹션 | API | 적용 시점 |
|---|---|---|
| 메이트 추천 | `/api/v1/home/mate-recommendations` | 최초 후보 선정 및 저장된 추천의 현재 노출 재검증 |
| 같은 여행지 동행 | `/api/v1/home/same-destination-trips` | 요청 시 실제 게시글 조회 |
| 또래 동행 | `/api/v1/home/same-age-trips` | 요청 시 실제 게시글 조회 |

위 3개의 API 모두 로그인 사용자를 기준으로 합니다. 인기 여행지는 여행지 집계이며, 다가오는 여정은
참여 중인 여정 조회이므로 이 필터를 일괄 적용하지 않습니다. 일반 게시글 검색에도 자동 적용하지 않습니다.

## 공통 필수 조건

아래 여섯 조건은 세 추천 모두 적용합니다. 하나라도 만족하지 않으면 후보/노출 대상에서 제외합니다.

| 조건 | 현재 구현 기준 | 경계 및 주의사항 |
|---|---|---|
| 삭제되지 않은 글 | `isDeleted = false` | soft delete된 글 제외 |
| 모집 중인 글 | `status = OPEN` | 그 외 상태 제외 |
| 정원 미달 | `recruitCount < recruitCapacity` | 정원과 같거나 초과하면 제외 |
| 여행이 끝나지 않은 글 | `endDate >= today` | 종료일이 오늘이면 포함 |
| 본인 작성 글 제외 | 작성자 ID ≠ 현재 사용자 ID | 동행 상대를 찾는 추천 기준 |
| 본인이 신고한 글 제외 | 현재 사용자와 게시글의 신고 이력이 없음 | 신고 상태와 무관, 다른 사용자의 신고만으로 제외하지 않음 |

`today`는 `TimeProvider`의 한국 시간(KST) 날짜를 사용합니다.
여행 시작일이 과거라는 이유만으로 제외하지 않으므로 진행 중 여행도 공통 조건을 통과할 수 있습니다.
단, 메이트 추천의 사용자 가능 날짜 등 별도 조건에 따라 추가로 제외될 수 있습니다.

## 모집 마감일과 모집 상태

모집 가능 여부는 세 섹션 모두 `status = OPEN`으로 판단합니다. 조회 시 `recruitDeadline`을 별도로
검사하지 않습니다.

모집 마감일이 지난 `OPEN` 게시글은 자정 스케줄러가 `CLOSED`로 전환합니다. 따라서 스케줄러가 상태를
전환하기 전까지는 조회 조건상 노출될 수 있으며, 홈 추천 조회에서 마감일로 별도 차단하지 않습니다.

마감일이 오늘인 게시글은 스케줄러 전환 대상이 아니므로 `OPEN`이면 노출됩니다. 마감일이 없는 게시글도
같은 방식으로 상태값만 따릅니다.

## 추천별 추가 조건

아래는 적용 차이를 찾기 위한 요약이며, 상세 정책은 연결된 문서를 기준으로 합니다.

| 항목 | 메이트 추천 | 같은 여행지 동행 | 또래 동행 |
|---|---|---|---|
| 여행지 선호 | 설정된 전체 선호를 OR로 적용 | 1순위 도시·국가만 적용 | 미적용 |
| 사용자 가능 날짜 | 설정 시 동행 방식별 적용 | 미적용 | 미적용 |
| 게시글의 참가자 성별·나이 조건 | 적용 | 미적용 | 미적용 |
| 작성자와 사용자의 나이 차이 | ±5세 조건 없음 | 미적용 | 만 나이 차이 ±5세 이내 |
| 참여 신청 이력 | 상태와 무관하게 제외 | 미적용 | 미적용 |
| 추천 패스 이력 | 제외 | 미적용 | 미적용 |
| 작성자 정보 | 생성 시 여행 성향, 카드 조회 시 필요한 프로필 확인 | 추가 프로필 조건 없음 | 프로필·생년월일 필요 |

또래의 ±5세 조건은 **작성자의 나이**를 비교하며, 게시글이 지정한 참가자 나이 범위와 다릅니다.
성별·나이·신청 이력을 필터링하지 않는 섹션도 있으므로, 홈에 노출됐다는 이유만으로 실제 신청 가능을
보장하지 않습니다. 참여 신청 API의 현재 상태 및 자격 검증은 별도로 유지합니다.

## 정렬·개수·빈 결과

조건은 후보를 고르는 기준이며 정렬과 추천 제공량은 별도 정책입니다.
같은 여행지·또래 동행은 조건 적용 후 오래된 순으로 최대 30개를 후보로 조회하고, 호출마다 그중
무작위 3개를 반환합니다. 후보가 3개 미만이면 전부 반환하며, 조건을 완화해 개수를 채우지 않습니다.
메이트 추천은 점수 기반 일일 묶음을 생성하고,
저장 순위대로 재검증하며 숨겨진 카드를 당일 보충하지 않습니다.
선호 미설정·생년월일 누락·설문 미완료는 단순 후보 없음과 다르므로 각 섹션의 상태 계약을 따릅니다.

- 메이트 후보 선정: [RecommendablePostQueryRepository](../../src/main/java/com/dduru/gildongmu/recommendation/repository/RecommendablePostQueryRepository.java)
- 메이트 현재 노출 재검증: [MateRecommendationCardQueryRepository](../../src/main/java/com/dduru/gildongmu/recommendation/repository/MateRecommendationCardQueryRepository.java)

정책 문서의 공통화와 코드의 공통화는 다릅니다. 현재 세 섹션이 동일한 공통 메서드를 호출하는 것은 아닙니다.
공통 정책 수정 시 위 세 구현과 해당 테스트를 함께 확인해야 합니다.

필수 회귀 검증은 종료일의 어제·오늘·내일, `OPEN` 상태의 마감일 경과·오늘·미설정, 정원 미달·동일·초과,
삭제·OPEN 이외 상태, 본인 글, 본인/타인의 신고, 진행 중 여행, 유효 후보 0~3개 이상입니다.
메이트 추천은 최초 생성 후 게시글 상태가 바뀐 경우의 재검증도 확인합니다.
