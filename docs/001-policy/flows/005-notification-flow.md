# 005. Notification Flow

> 알림 서비스는 도메인 이벤트를 수신해 수신자에게 인앱 알림을 생성·저장하고,
> FCM 푸시 알림을 비동기로 발송하며, 사용자가 알림함에서 조회·읽음 처리하는 흐름이다.

이 문서는 `알림` 기능을 처음 보는 사람이 아래를 한 번에 이해할 수 있도록 정리한 제품 흐름 문서다.

- 알림이 어떤 조건에서 생성되는지
- 푸시 알림 수신 설정이 어떻게 적용되는지
- 알림 타입별 수신자 결정 규칙
- 알림함 조회와 읽음 처리 정책
- 예외 처리 및 격리 정책

---

## 1. 핵심 컨셉

### 사용자가 직접 생성하지 않는다

사용자가 직접 임의 알림을 생성할 수는 없다. 알림은 신청, 승인, 공지 등록, 일정 변경처럼
사용자 행동이나 시스템 스케줄에 의해 생성된다.

### 알림 생성 시점의 정보를 사용한다

알림 문구와 수신자는 알림이 생성되는 시점의 정보를 기준으로 결정한다.

예) 매칭 신청 알림에는 신청 시점의 신청자 닉네임을 사용한다.

### 알림 저장 실패는 본문 트랜잭션에 영향을 주지 않는다

알림 저장이나 푸시 발송이 실패해도 매칭/일정 처리 결과는 그대로 유지된다.

---

## 2. 알림 생성 정책

알림은 도메인 이벤트 또는 스케줄러를 통해 생성된다. 사용자가 직접 임의 알림을 생성하는 기능은 제공하지 않는다.

- 인앱 알림은 사용자의 푸시 수신 설정과 무관하게 저장한다.
- FCM 푸시는 푸시 수신 설정이 켜진 사용자에게만 발송한다.
- FCM 발송 실패는 인앱 알림 저장이나 원래 도메인 동작에 영향을 주지 않는다.
- 채팅 메시지는 인앱 알림함에 저장하지 않고 FCM 푸시만 발송한다.

### FCM 토큰 라이프사이클

앱은 로그인, 토큰 갱신, 로그아웃 시점에 푸시 토큰 상태를 서버와 동기화해야 한다.
같은 토큰이 다른 사용자에게 등록된 경우에는 현재 사용자 기준으로 갱신한다.

알림 생성과 푸시 발송의 내부 구현 세부는 [알림 구현 문서](../../004-implementation/005-notification.md)에 둔다.

---

## 3. 알림 타입별 규칙


### 수신자 결정

| 타입 | 수신자 | 결정 방식 |
|---|---|---|
| `MATCH_APPLIED` | 모집글 작성자 1명 | 이벤트에 `recipientUserId` 포함 |
| `MATCH_APPROVED` | 신청자 1명 | 이벤트에 `applicantUserId` 포함 |
| `JOURNEY_NOTICE` | 여정 ACTIVE 멤버 전원 (행위자 제외) | 여정 ACTIVE 멤버 기준 |
| `SCHEDULE_CREATED / UPDATED / CANCELED` | 여정 ACTIVE 멤버 전원 (행위자 제외) | 여정 ACTIVE 멤버 기준 |
| `POST_UPDATED` | 해당 모집글을 찜한 유저 전원 | 해당 모집글을 찜한 유저 기준 |
| `TRIP_UPCOMING` | 여정 ACTIVE 멤버 전원 | 스케줄러에서 여정 ACTIVE 멤버 기준 |

> 행위자 본인은 항상 수신자에서 제외된다. (`TRIP_UPCOMING` 제외)

### 알림 문구(body)

| 타입 | body |
|---|---|
| `MATCH_APPLIED` | `{닉네임} 님이 매칭을 신청했습니다.` |
| `MATCH_APPROVED` | `{닉네임} 님과 매칭이 성사되었습니다.` |
| `JOURNEY_NOTICE` | `{여행지/방 이름} 에 공지가 등록되었습니다.` |
| `SCHEDULE_CREATED` | `{일정 이름} 일정이 추가되었습니다.` |
| `SCHEDULE_UPDATED` | `{일정 이름} 일정이 변경되었습니다.` |
| `SCHEDULE_CANCELED` | `{일정 이름} 일정이 취소되었습니다.` |
| `POST_UPDATED` | `관심 있는 모집글에 변경이 있습니다.` |
| `TRIP_UPCOMING` | `곧 여행이 시작됩니다. 준비물은 다 챙기셨나요?` |

> `MATCH_APPLIED`의 닉네임은 신청자, `MATCH_APPROVED`의 닉네임은 승인자(모집글 작성자)이다.
> 닉네임은 알림 생성 시점의 사용자 정보를 기준으로 한다.

### 알림 이동 대상

알림에는 이동 대상 정보가 포함된다. 푸시 알림과 인앱 알림함은 동일한 이동 규칙을 사용한다.

| 알림 종류 | 이동 대상 | 대상 기준 |
|---|---|---|
| `MATCH_APPLIED` | 신청 목록 | 참여 신청 |
| `MATCH_APPROVED` | 여정 상세 | 승인된 여정 |
| `JOURNEY_NOTICE` | 공지 상세 | 등록된 공지 |
| `SCHEDULE_*` | 일정 상세 | 생성/변경/취소된 일정 |
| `POST_UPDATED` | 모집글 상세 | 변경된 모집글 |
| `TRIP_UPCOMING` | 여정 상세 | 여행이 임박한 여정 |
| 채팅 메시지 | 채팅방 | 메시지가 도착한 채팅방 |

> 채팅 메시지 알림은 인앱 알림함에는 표시되지 않고, 푸시 알림에서만 채팅방 이동 정보를 전달한다.

---

## 4. JOURNEY_NOTICE 중복 발송 방지

공지 알림은 게시글이 비공지 상태에서 공지 상태로 전환될 때만 발송한다.
공지 해제 후 재지정 시에는 새 공지 등록으로 보고 알림을 다시 발송한다.

---

## 5. 알림함 조회 정책


### 알림 목록

알림 목록은 최근 한 달의 삭제되지 않은 알림을 ID 내림차순으로 조회한다.
한 달은 조회 시각에서 달력 기준 한 달 전부터이며 고정 30일이 아니다.
기본 페이지 크기는 20, 최대 50이며 커서로 다음 페이지를 조회한다.

- 전체: 모든 인앱 알림
- 읽지 않음: 미읽음 인앱 알림
- 모집·매칭: 매칭 신청, 매칭 승인, 찜한 글 변경
- 여정: 공지 등록, 일정 생성/변경/취소, 여행 임박

미읽음 배지는 전체·모집/매칭·여정별로 제공하며 목록과 동일한 기간 및 삭제 조건으로 집계한다.
채팅 메시지는 이 목록에 포함하지 않는다.

### 읽음 처리

- 최근 한 달의 삭제되지 않은 본인 알림에 대한 단건 읽음 처리를 제공한다.
- 전체 읽음은 선택한 탭과 무관하게 최근 한 달의 삭제되지 않은 본인 알림에 적용한다.
- 이미 읽은 알림을 다시 읽음 처리해도 에러 없이 성공한다.

### 전체 삭제

- 선택한 탭과 무관하게 최근 한 달의 본인 알림을 전체 소프트 삭제한다.
- 삭제한 알림은 목록과 미읽음 개수에서 제외한다.
- 삭제할 알림이 없어도 성공한다.
- 발송 이력은 남겨 여행 임박 알림의 중복 발송을 방지한다.
- 기간이 지난 알림의 자동 물리 삭제는 이번 범위에 포함하지 않는다.

조회·읽음·삭제의 API 계약은 [알림 구현 문서](../../004-implementation/005-notification.md)에 둔다.

---

## 6. 예외 처리

| 상황 | 처리 원칙 |
|---|---|
| 존재하지 않는 알림 ID | 실패로 처리 |
| 삭제되었거나 조회 기간이 지난 알림 읽음 처리 | 알림을 찾을 수 없음으로 처리 |
| 타인의 알림 읽음 처리 시도 | 실패로 처리 |
| 이미 읽은 알림 재처리 | 에러 없이 멱등 처리 |
| 수신자 0명 (행위자 제외 후) | 알림을 생성하지 않고 정상 처리 |
| 알림 저장 실패 | 로그만 남기고 원래 동작에는 영향 없음 |

---

## 7. 여행 임박 알림 (TRIP_UPCOMING)

여행 임박 알림은 이벤트 기반이 아니라 스케줄러 기반으로 발송한다.
여행 시작 3일 전인 여정의 ACTIVE 멤버에게 발송하며, 같은 날 같은 멤버에게 중복 발송하지 않는다.

---

## 8. 알림 수신 설정

- 사용자는 푸시 알림 수신 여부를 전체 on/off로 설정할 수 있다.
- 기본값은 on이다.
- off 시 FCM 푸시만 차단하고, 인앱 알림은 계속 저장한다.
- 설정은 1:1 알림과 그룹 알림에 모두 동일하게 적용한다.

---

## 9. 채팅 메시지 FCM 푸시

채팅 메시지는 인앱 알림함에 저장하지 않고 FCM 푸시만 발송한다.
채팅방에 접속 중인 사용자는 이미 WebSocket으로 메시지를 받고 있으므로 푸시 대상에서 제외한다.
연속 메시지는 같은 채팅방 기준으로 일정 시간 동안 묶어 과도한 푸시를 방지한다.

채팅 메시지 푸시의 내부 구현 세부는 [알림 구현 문서](../../004-implementation/005-notification.md)에 둔다.

---

## 10. 현재 범위 제외 항목


- `SCHEDULE_UPCOMING` — 시간 기반 스케줄러 + 푸시 연동 필요
- 채팅 메시지 인앱 알림 저장
- 시스템 공지/이벤트 (어드민 발송)
- 90일 경과 알림 자동 삭제 배치
