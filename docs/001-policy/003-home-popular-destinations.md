# 홈 인기 여행지 정책

#331의 최초 OPEN 방 수 정렬안을 전체 기간 누적 생성 수 정렬로 변경한 확정 정책입니다.

## 인기 기준

모든 사용자에게 동일한 여행지 카드를 가로 스크롤로 최대 5개 제공합니다. 전체 기간에 생성된
삭제되지 않은 여행방 수로 정렬하며, 마감된 방도 생성 실적에 포함합니다. 동률이면 여행지 ID가 작은 순입니다.
등록된 여행지를 단위로 집계하므로 제주·제주시 등 별도 여행지 데이터를 합치지 않습니다.

카드 숫자는 현재 OPEN이고 삭제되지 않은 방 수입니다. 기간 제한은 없으며 사용자의 성별·나이·신청 이력이나
방 정원·종료일 등을 별도 필터링하지 않습니다. 따라서 개인별 신청 가능 수로 표시하지 않고 “현재 열린 여행방”으로 안내합니다.

## 부족한 지역 보충

실제 인기 지역을 먼저 배치하고, 중복 없이 아래 순서로 기본 추천 지역을 채웁니다.

제주(KR) → 부산(KR) → 강릉(KR) → 후쿠오카(JP) → 오사카(JP) → 서울(KR) → 도쿄(JP) → 교토(JP) → 방콕(TH) → 다낭(VN)

도시명과 국가 코드를 함께 사용합니다. 로컬 DB의 제주 명칭은 “제주”입니다. 없는 지역은 건너뛰고,
기본 목록으로도 부족하면 나머지 등록 지역을 ID 오름차순으로 채웁니다. 여행지 자체가 5개 미만이면 있는 만큼 반환합니다.
여행지 데이터를 새로 만들거나 게시글·통계를 조작해서 개수를 채우지 않습니다.

보충 카드는 “추천 여행지”로 표시하고 순위 배지는 숨깁니다. 누적 생성 수와 현재 열린 방 수는 모두 0이며 태그는 빈 배열입니다.

## 화면 표시

- 실제 인기 지역이 있으면 “인기 여행지”, 모두 기본 추천이면 “이런 여행지는 어때요?”로 표시합니다.
- “전체 기간 누적 생성 기준”과 updatedAt 기반 갱신 시각(예: “14:00 기준”, “20분 전 갱신”)을 안내합니다. 최대 1시간 동안 집계 결과를 재사용하며 자동 갱신 푸시는 제공하지 않습니다.
- 카드 선택 시 여행지로 필터링된 동행 목록으로 이동합니다. 열린 방이 없으면 빈 목록과 글 작성 진입점을 제공합니다.
- 이미지가 없으면 클라이언트 기본 이미지를 사용합니다. 여행지 자체가 없으면 섹션을 숨깁니다.

태그도 순위와 동일하게 삭제되지 않은 전체 기간 게시글에서 게시글당 한 번씩 집계합니다. 공백과 빈 태그를 정리하고
빈도 내림차순·문자열 오름차순으로 최대 3개만 제공합니다. 부족한 태그는 보충하지 않습니다.

## 갱신과 오류

집계 응답을 1시간 동안 재사용합니다. 새 방·삭제·마감·여행지/태그 수정은 캐시 만료 후 다음 조회에 반영됩니다.
Redis 장애 시 DB에서 직접 집계합니다. DB까지 실패하면 해당 섹션 오류로 처리하며,
정상적인 “데이터 없음”이나 기본 추천으로 위장하지 않습니다.
