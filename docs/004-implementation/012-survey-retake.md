# 012. 성향 테스트 재테스트 구현

제품 규칙은 [성향 테스트 재테스트 정책](../001-policy/005-survey-retake.md)을 따릅니다.

## 저장 및 기존 회원 적용

`V38__add_survey_last_retested_at.sql`에서 `surveys.last_retested_at`을 nullable DATE 컬럼으로 추가합니다.

- `NULL`: 즉시 재테스트 1회를 사용할 수 있는 상태입니다. 가입 시 최초 제출은 이 값을 채우지 않습니다.
- 날짜: 마지막으로 성공한 재테스트 날짜이며, 이 날짜에 30일을 더한 날부터 다음 수정이 가능합니다.

기존 행은 모두 `NULL`로 유지하여 기존 가입자에게도 즉시 1회를 제공합니다. 기존 `created_at`, `modified_at`은 변경하지 않습니다. 마이그레이션 적용 후 애플리케이션의 새 재테스트 로직을 사용합니다.

## 처리 및 응답

`SurveyService.update`는 설문 행을 비관적 쓰기 잠금으로 조회하고, 가능 여부 검증과 답변·재테스트 날짜·성향·아바타 갱신을 한 트랜잭션으로 처리합니다. 동일 답변도 재테스트 날짜가 저장되며, 실패 시 전체 변경이 롤백됩니다.

`TimeProvider.today()`의 KST 날짜를 사용합니다. 일반 엔티티 수정 시각 대신 별도 재테스트 날짜로 제한을 계산합니다.

| 응답 필드 | 재테스트 전 | 재테스트 후 |
|---|---|---|
| `lastTestedAt` | 기존 최근 테스트일 (`modified_at`), 최초 제출 응답은 제출일 | 마지막 재테스트일 |
| `canRetake` | `true` | 오늘이 마지막 재테스트일 + 30일 이상인지 여부 |
| `nextRetakeAvailableDate` | 조회/제출 당일 | 마지막 재테스트일 + 30일 |
| `remainingRetakeDays` | `0` | 가능일까지 남은 일수, 가능하면 `0` |

수정 가능일 전 제출은 기존 `SURVEY_RETAKE_LOCKED`(HTTP 429) 응답을 유지합니다. API 필드 구조는 변경하지 않습니다.

## 검증

- 최초 제출 후 즉시 재테스트 가능 여부와 결과 조회 응답
- 첫 재테스트 및 30일 경과 후 재테스트 성공과 제한 갱신
- 당일·29일째 수정 거절, 30일째 수정 허용
- 동일 답변 제출 시 날짜 저장과 중복 요청 차단
- 동시 요청 중 1건만 성공
- 실패 시 재테스트 날짜 및 성향 저장 롤백
- 기존 수정 이력과 관계없이 마이그레이션 후 즉시 1회 제공
