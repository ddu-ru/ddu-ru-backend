# 013. 휴대폰 인증 만료·재시도 처리

API 응답과 앱 표시 기준은 [휴대폰 인증 앱 연동 가이드](../003-api/006-phone-verification.md)를 참고합니다.

## Redis 저장 및 만료

기존 키와 JSON 구조를 유지합니다. DB 마이그레이션이나 Redis 데이터 초기화는 필요하지 않습니다.

| 키 | 저장 내용 | 만료 정책 |
|---|---|---|
| `sms:auth:{phone}` | `code`, `phone`, `count`, `status` JSON | PENDING은 최초 발급부터 3분, VERIFIED는 검증 성공부터 10분 |
| `sms:resend:{phone}` | `1` | 발송 성공 후 60초 |
| `sms:daily:{phone}` | 발송 횟수 | 최초 카운터 생성부터 24시간, 최대 50회 |

`TimeProvider.instant()`로 밀리초 단위 발급 만료 시각을 한 번 계산하고, `SET PXAT`과 KST `expiresAt` 응답에 동일한 시각을 사용합니다.

재발송 제한은 Redis에서 설정한 직후 `PEXPIRETIME`을 반환하며, 성공 응답의 `resendAvailableAt`에는 이를 `+09:00`의 `OffsetDateTime`으로 변환해 제공합니다.

제한 오류도 판정과 `PEXPIRETIME` 조회를 같은 Lua 실행에서 처리합니다. 서버는 실제 만료 시각에서 `TimeProvider.instant()`를 뺀 남은 시간을 초 단위로 올림하고, 0 이하이면 0초로 제한합니다. 이 값은 `RetryableBusinessException`을 통해 전달되어 HTTP `Retry-After` 헤더로만 노출됩니다. `ErrorData`와 `ErrorResponse`는 기존 구조를 그대로 사용합니다.

## 원자적 처리

Lua 스크립트는 `src/main/resources/redis/verification/`에서 관리합니다.

- 인증 검증: 조회, 만료·상태 확인, 코드 비교, 실패 횟수 증가를 한 번에 실행합니다. 오입력 시 `SET XX KEEPTTL`로 기존 만료를 유지합니다. 이미 만료된 키는 재생성하지 않습니다.
- 시도 횟수: 기존 판정을 유지합니다. 오입력 1~5회는 `INVALID_AUTH_CODE`, 6번째 오입력은 키 삭제 후 `VERIFICATION_ATTEMPTS_EXCEEDED`입니다. 인증 성공은 `VERIFIED`로 전환하고 10분을 유지하며 후속 검증은 `ALREADY_VERIFIED`입니다.
- 발송 제한: 일일 한도, 재발송 제한을 순서대로 확인한 뒤 허용된 요청만 카운터를 증가시킵니다. 거절된 요청은 횟수와 제한 만료를 바꾸지 않습니다.
- 발송 실패: 인증 키 삭제와 횟수 차감을 함께 처리합니다. 만료된 카운터를 음수·무기한 키로 재생성하지 않고, 횟수가 0이 되어도 살아 있는 최초 24시간 만료는 유지합니다.
- 비정상 데이터: 인증·제한 키에 만료 시간이 없으면 내부 오류로 처리합니다. 임의의 만료 시각이나 대기 시간을 만들거나 인증을 허용하지 않습니다.

외부 SMS 발송 자체는 Redis 트랜잭션에 포함되지 않습니다. 이번 변경은 동시 인증 검증과 제한 판정의 일관성을 보완하며, 외부 발송의 멱등성이나 동시 발송 예약 구조는 변경하지 않습니다.

## 배포와 검증

저장소 배포 설정과 동일한 Redis 7을 사용합니다. `PEXPIRETIME`은 Redis 7 명령이므로 서버의 Redis 버전을 유지해야 합니다. 기존 PENDING 데이터는 현재 남아 있는 TTL부터 연장을 막으며, 이미 과거 로직으로 연장된 만료 시각을 소급 복원하지 않습니다.

- 실제 Redis 7: 발급 응답과 만료 시각 일치, 오입력 후 만료 유지, 동시 오입력 횟수 누락 방지, 동시 정상 검증 1회 성공.
- 만료 경계: 만료된 코드 거절·재생성 방지, 비정상 TTL 차단, 만료된 카운터 롤백 시 무기한 키 생성 방지.
- 제한: 재발송 가능 시각과 제한 오류 시각 일치, 거절 시 횟수 유지, 최초 24시간 만료 유지 및 만료 후 새 카운터 생성.
- 서비스·API: SMS 실패 회귀, 일반·관리자 발송 응답, 기존 KST `expiresAt` 형식, 성공 응답의 `+09:00` 시각, 제한 오류 본문의 기존 구조 유지, `Retry-After` 정수 초 및 올림·0초 경계, 성공·무관한 오류에서 헤더 생략.
