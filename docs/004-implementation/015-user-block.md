# 015. 사용자 차단 구현

## 저장 모델

`user_blocks`는 차단자와 차단 대상의 방향성을 보존합니다. `(blocker_user_id, blocked_user_id)`는 유니크하며, 한 사용자가 같은 상대를 여러 번 차단해도 관계는 한 건만 유지합니다.

차단 등록은 두 사용자 행을 사용자 ID 오름차순으로 잠근 뒤 기존 관계를 확인합니다. 같은 쌍에 대한 동시 차단 요청도 동일한 잠금 순서를 사용해 중복 저장을 막습니다.

## API

| Method | URL | 설명 |
|---|---|---|
| PUT | `/api/v1/users/me/blocks/{targetUserId}` | 사용자 차단 |
| DELETE | `/api/v1/users/me/blocks/{targetUserId}` | 내 차단 해제 |
| GET | `/api/v1/users/me/blocks` | 내 차단 목록, 최근 차단순 커서 페이지 조회 |

목록 항목은 `userId`, `nickname`, `bio`, `profileImage`을 반환해 차단 목록 화면의 프로필·해제 버튼에 사용합니다.

## 적용 정책표

차단 관계는 단방향으로 저장하지만, 노출과 상호작용은 어느 한쪽이라도 상대를 차단하면 제한한다.

| 영역 | 차단 관계에서의 처리 | 응답·노출 정책 |
|---|---|---|
| 차단 등록·해제 | 요청한 사용자가 설정한 방향만 변경 | 중복 등록·해제도 `204` |
| 게시글 상세 | 접근을 거절하고 조회수를 증가시키지 않음 | `404 POST_NOT_FOUND` |
| 게시글·찜·홈·추천 목록 | DB 조회 단계에서 상대 게시글 제외 | 정상 응답에서 미노출 |
| 추천 | 후보 생성과 저장된 추천 카드 응답에서 각각 제외 | 정상 응답에서 미노출 |
| 신규 1:1 채팅 | 방 생성 거절 | 게시글 기반 생성은 `404 POST_NOT_FOUND` |
| 기존 1:1 채팅 | 기록과 방은 유지하고 새 메시지 전송 거절 | `404 CHAT_ROOM_NOT_FOUND` |
| 신규 동행 신청·신청 연락·승인 | 상호작용 거절 | 신청은 `POST_NOT_FOUND`, 연락·승인은 `PARTICIPATION_NOT_FOUND` |
| 기존 공동 여정·그룹 채팅 | 차단만으로 멤버십을 변경하지 않고 이용 유지 | 기존 여정 권한 적용 |
| 여정 공지·일정·여행 임박 알림 및 푸시 | ACTIVE 여정 멤버라면 계속 수신 | 공동 여정 필수 정보 예외 |

### 차단 관계 비노출

- 사용자·게시글·채팅방 등 요청한 리소스가 실제로 없으면 각 도메인의 `404 Not Found`를 반환한다.
- 리소스는 존재하지만 차단 관계로 상세 접근이나 상호작용을 제한해도 실제 부재와 동일한 도메인 `404 Not Found`를 반환한다.
- 목록과 추천은 항목 단위 오류를 반환하지 않고 쿼리에서 제외한다.
- 차단 여부를 추론할 수 없도록 외부 응답에는 `USER_BLOCKED`나 공통 `NOT_FOUND`처럼 실제 부재와 구분되는 오류 코드 또는 차단 문구를 포함하지 않는다.
- 현재 공개 상대 프로필 상세 API는 없지만, 해당 API를 도입할 때도 같은 비노출 원칙을 적용한다.

### 공동 여정 알림 예외

사용자 차단은 개인 관계의 노출과 신규 상호작용을 제한하는 기능이며, 기존 여정 멤버십을 해제하거나 상대를 여정에서 내보내는 기능이 아니다. 따라서 ACTIVE 멤버에게 필요한 다음 정보는 차단 관계와 무관하게 유지한다.

- 그룹 채팅 메시지와 메시지 푸시
- 여정 공지 등록 알림
- 일정 생성·변경·취소 알림
- 여행 임박 알림

여정에서 제외되거나 탈퇴해 ACTIVE 멤버가 아니게 되면 차단 여부가 아니라 여정 접근 정책에 따라 그룹 채팅과 여정 알림 대상에서 제외된다.

## 검증

- 자기 자신 차단, 중복 차단, 반복 해제
- 양방향 차단 관계의 접근 거절
- 목록 빈 상태·커서 페이지
- 채팅, 참여 신청·연락·승인, 게시글·추천 조회 회귀
