# 015. 사용자 차단 구현

## 저장 모델

`user_blocks`는 차단자와 차단 대상의 방향성을 보존합니다. `(blocker_user_id, blocked_user_id)`는 유니크하며, 한 사용자가 같은 상대를 여러 번 차단해도 관계는 한 건만 유지합니다.

차단 등록은 두 사용자 행을 사용자 ID 오름차순으로 잠근 뒤 기존 관계를 확인합니다. 같은 쌍에 대한 동시 차단 요청도 동일한 잠금 순서를 사용해 중복 저장을 막습니다.

## API

| Method | URL | 설명 |
|---|---|---|
| PUT | `/api/v1/users/me/blocks/{targetUserId}` | 사용자 차단 |
| DELETE | `/api/v1/users/me/blocks/{targetUserId}` | 내 차단 해제 |
| GET | `/api/v1/users/me/blocks` | 내 차단 목록, 최근 차단순 커서 페이지 조회 |

목록 항목은 `userId`, `nickname`, `bio`, `profileImage`을 반환해 차단 목록 화면의 프로필·해제 버튼에 사용합니다.

## 적용 규칙

- 차단 등록·해제는 본인이 설정한 방향만 변경한다.
- 어느 한쪽의 차단 관계가 있으면 1:1 채팅 생성·전송, 신규 동행 신청, 신청 연락·승인을 거절한다.
- 게시글 상세 접근은 차단 관계가 있으면 거절하고 조회수도 증가시키지 않는다.
- 게시글 목록·찜 목록, 추천 후보·저장된 추천 카드, 슈퍼호스트 목록에서는 상대 게시글을 제외한다.
- 기존 공통 여정 및 그룹 채팅은 유지한다.

## 검증

- 자기 자신 차단, 중복 차단, 반복 해제
- 양방향 차단 관계의 접근 거절
- 목록 빈 상태·커서 페이지
- 채팅, 참여 신청·연락·승인, 게시글·추천 조회 회귀
