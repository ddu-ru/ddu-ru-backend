# 구현 문서

AI와 개발자가 기능 구현 시 참고할 세부 설계, 저장 모델, 테스트 방향을 정리합니다.

| 문서 | 한 줄 요약 |
|---|---|
| [나의 여정 구현 현황](./001-my-journey.md) | 나의 여정 API, 도메인 구현 상태, 설계 포인트 |
| [홈 여행방 추천 구현 문서](./002-recommendation.md) | 홈 여행방 추천 후보 조회, 점수 계산, 일일 묶음, 저장 모델, 테스트 방향 |
| [모집글 구현 문서](./003-post.md) | 모집글 목록/상세 응답, 검색/정렬, 생성/수정/삭제 구현 세부 |
| [참여 신청/그룹 채팅 구현 문서](./004-participation.md) | 참여 신청 상태 전이, 락 순서, 저장 모델, 서비스 책임 |
| [알림 구현 문서](./005-notification.md) | 알림 저장, FCM 푸시, 읽음 처리, 여행 임박 스케줄러 구현 기준 |
| [채팅 구현 문서](./006-chat.md) | 채팅방, 메시지 조회, 읽음 처리, 실시간 목록 갱신 구현 기준 |
| [선호 여행지 순위와 홈 동행](./007-home-destination-preference.md) | 선호 순위 저장, 홈 1순위 조회, 비활성 상태와 프런트 연동 |

## 문서 작성 기준

- 구현 문서에는 테이블명, 상태값, DTO, 쿼리 조건, 테스트 케이스처럼 구현 정확도에 필요한 내용을 둡니다.
- 사람이 합의해야 하는 제품 규칙은 [정책 문서](../001-policy/)에 먼저 정리합니다.
- 정책 변경으로 구현 세부가 바뀌면 정책 문서와 구현 문서를 함께 수정합니다.
